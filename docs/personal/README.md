# Personal Projects

Projects that are not Aspirationalist work. Real estate, household, family,
personal finance, and anything else that does not serve the platform.

This exists so personal work can use the same structure and the same agent
instructions as everything else in the repo without being mistaken for platform
work.

## Structure

Identical to `docs/projects/`:

```text
docs/personal/<project-name>/
├── README.md       ← purpose, outcome, status, boundaries, and navigation
├── source/         ← raw inputs and consolidated source notes
├── working/        ← synthesis, decisions, open questions, and drafts
├── canonical/      ← the current authoritative method for this project
└── artifacts/      ← polished outputs intended to be shared and used
```

Same maturity path: **source → working → canonical → artifact**. Create only the
folders the current work needs.

## What goes here

`docs/projects/` is the default. Most work overlaps with Aspirationalist enough to
belong there. Use `docs/personal/` only when a project clearly sits outside it.

When it is genuinely ambiguous, ask rather than guessing. Reclassifying later
breaks links.

## When personal work turns out to be useful

Don't move the project. Write the shareable version as an artifact under the
relevant topic or project in `docs/`, and link back here. A file has one primary
home.

## This repo is public

The transparency rules in `AGENTS.md` apply here unchanged — unfinished thinking,
mistakes, and personal context stay in.

What is different is that personal projects touch third parties and financial
specifics more often. Addresses, account numbers, counterparty names, and specific
financial figures get flagged for review rather than committed.

Flag the passage, not the project. Making a whole project private to hide one line
loses the context that makes the rest worth keeping.
