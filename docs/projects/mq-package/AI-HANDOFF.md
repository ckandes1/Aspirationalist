## Current project definition

The MQ Package is a chronological Gartner Magic Quadrant field guide supported by one operating workbook.

The field guide explains what to do, when to do it, what success looks like, and why. The workbook helps the coordinator run the process.

The MQ Package is not just a retrospective, a deck, a checklist, or a repository folder. It is a reusable operating package for running a vendor-side Gartner Magic Quadrant cycle from pre-season through post-season.

## Core thesis

The goal is not to move the dot.

The goal is to make the dot accurately reflect reality, then use the research to improve reality.

MQ project success should be assessed at four levels:

1. **Accurate evaluation:** the analyst firm receives complete, credible, current evidence and the vendor does not leave earned credit on the table.
2. **Strategic understanding:** the company uses the evaluation, criteria, analyst feedback, and competitive context to understand the market more clearly.
3. **Business improvement:** leadership turns findings into decisions about product, roadmap, evidence, strategy, positioning, and investment.
4. **Compounding performance:** those decisions improve actual market performance, which improves future evaluations downstream.

The dot is a lagging indicator. Zone 2 protects the accuracy of the reflection. Zone 1 improves the thing being reflected.

## Source-of-truth rules

Some duplication is expected.

The same idea may appear in raw notes, decks, Drive drafts, GitHub source files, and working decisions. That is not automatically a problem.

Duplication becomes a problem only when there are competing active sources of truth.

Use this rule:

- Raw examples and messy inputs belong in Drive Source Library or GitHub source files.
- Current project coordination belongs in Drive Project Control.
- Current decks and drafts belong in Drive.
- Durable decisions belong in GitHub working or canonical files.
- Final reusable methods should eventually move to GitHub canonical files.

If Drive and GitHub disagree:

- Drive may be newer and messier.
- GitHub may be more structured but slightly behind.
- Do not silently reconcile conflicts.
- Tell Keith what differs and ask which source should win before making durable changes.
