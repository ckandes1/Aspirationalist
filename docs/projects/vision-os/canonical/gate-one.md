# Gate One: The Idea Murder Machine

Status: canonical on merge. Derived from `../source/idea-murder-machine-gate-one.md` and `../source/idea-murder-machine-project-foundation.md`. Wording stays close to Keith's originals.

## Where this sits

The Vision OS blueprint (`operational-blueprint.md`) places the Idea Murder Machine between the Vision Deck and the One Hypothesis. Gate One is the first and most detailed stage of that filter. It decides whether an idea survives long enough to be considered for the hypothesis slot.

The model comes from the X/Alphabet moonshot factory approach of killing the magic early: find the load-bearing assumption, design the cheapest possible test, and let a failed test end the idea. Good ideas are cheap to falsify. If testing needs a large upfront investment, that is a red flag about the idea.

## When to run it

Run every new idea through Gate One before any planning, building, or designing begins. Ask each question explicitly. Do not skip to solution mode until all five have honest answers. A failed idea is named dead or shelved, and the work moves on without guilt.

## The five questions

Ask them in order. Stop at the first failure.

**1. Do I actually care about this?**
Gut check first. How excited is Keith about the idea, and does it have real potential for him and for the people it would serve? If the honest answer is "not really," stop. A perfectly testable idea he does not care about still wastes time.

**2. What is the idea at its simplest, and what is the artifact?**
State the core idea in two or three sentences with no jargon and no qualifications. If it cannot be stated simply, it is not understood well enough yet. Then name the artifact: what is being built, what form it takes, and what someone does with it. If the artifact cannot be named, the idea is not ready to become a project.

Choose the artifact with the Artifact Ladder below.

**3. What is the load-bearing assumption?**
Every idea has one thing that, if false, kills it. It is usually the thing Keith most hopes is true and has not verified. Name it explicitly. This is the thing about to be tested.

**4. What does minimum viability look like?**
Drop the full vision. Describe the smallest real version that would be useful to someone. Name who it serves and what they do differently because of it. If those answers are not concrete, the idea is not ready.

**5. What is the cheapest way to test the load-bearing assumption?**
Name the scrappiest test that would show in hours or days, not weeks, whether the assumption is true or false. If no cheap test can be designed, that is a red flag. If the idea passes the test, it moves forward. If it fails, it is dead.

## The Artifact Ladder

Start at the lowest rung that makes the idea useful. Climb only when the action requires it.

Thought → Content → Checklist/Guide → Template/Playbook → Toolkit → Software

The test for choosing a rung: what is the smallest thing someone could do differently because of this?

- If that cannot be answered, the idea is not ready.
- The answer usually decides the artifact type.
- A spreadsheet with formulas is the most primitive software.
- Software is justified when an action must repeat over time with dynamic inputs.

Content only counts as an artifact when it changes what someone does. Keith's recurring failure point is stopping one step before that. The check is always: what does someone do with this?

## What happens when an idea passes

Before the conversation ends, define the next concrete action.

In this repository, passing Gate One makes an idea a candidate for the One Hypothesis slot. It does not create a project by itself. A project still needs a charter (vision link, active hypothesis, kill criteria, 30 to 90 day scope, status) and a free slot under the three active priorities rule. The agent drafts what it can and leaves the hypothesis and kill criteria as `TODO`s for Keith.

## Open questions

- How the answers to questions 3 and 5 feed the charter's active hypothesis and kill criteria is not yet defined. The match looks likely, and it has not been confirmed.
- Gate One has not yet been run on a live idea inside this repository. The first run is the real test of whether it holds up.
