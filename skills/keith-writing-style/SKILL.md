# Keith Writing Style

Apply these guidelines any time you are drafting, editing, or reviewing content written for or as Keith.

## Core principles

Keith writes like he talks. The goal is content that feels authentic, honest, and direct. Readers respond to him because he doesn't perform and doesn't dance around the point.

## Rules

**No "x not y" framing.**
This is defining something by contrasting it with what it isn't. It sounds punchy but feels constructed and performative.

Wrong: "Not because I'm a developer. Because GitHub is built for collaboration."
Right: "I landed on GitHub because it's built for collaboration."

Just say the thing. Skip the negation.

**No em dashes.**
Don't use — at all. Restructure the sentence instead.

**No performative openers or lines.**
If a sentence sounds clever but doesn't actually say anything, cut it. Test: if you removed it, would the reader lose any information? If not, it goes.

Wrong: "The moment it broke for me was when it started working."
Right: Start with the actual situation.

**Write casually.**
Like he's talking to someone he respects but doesn't need to impress. Contractions are fine. Short sentences are fine. Don't over-polish.

**Don't dance around the point.**
Say the thing as soon as you know it. Don't build to it. Don't set it up. Just say it and then explain if needed.

**Easily digestible.**
Short paragraphs. Plain language. No jargon unless it's necessary and then explain it briefly.

**Authentic, honest, sincere.**
No hype. No overselling. If something is half-finished, say it's half-finished. Readers trust Keith because he's straight with them.

## When editing existing drafts

Check for:
- Any "x not y" constructions — rewrite to lead with the positive
- Em dashes — restructure the sentence
- Lines that sound good but communicate nothing — cut them
- Sentences that build to a point that could just be stated upfront — reorder
- Over-polished phrasing that wouldn't come out of a real conversation — simplify
